# Решения по ТЗ

Уточнения к `docs/SPEC.md`, согласованные с заказчиком. Номера — вопросы из обсуждения ТЗ.

## Организации и доступ

1. **Регистрация:** клиника регистрируется сама (форма «создать клинику» → организация + пользователь-владелец). Биллинг: тарифы и оплаты (отдельный этап; в схеме закладываем `plan`/`subscription` на организацию).
6. **Видимость сделок для `manager`:** настраивается в организации (например: только свои / свои + нераспределённые / все).
7. **«Кто первый ответил»:** участвуют только выбранные ответственные сотрудники (настраивается список).
8. **Роли:** владелец = руководитель + биллинг + управление сотрудниками.
9. **Вход и приглашения:** по email (нужен SMTP для Supabase Auth).

## Сущности

3. **Валюта:** только тенге (KZT). Оплаты — таблица платежей (сумма + дата), «оплачено» = сумма платежей.
4. **Несколько открытых сделок у пациента:** входящее сообщение прикрепляется к последней обновлённой открытой сделке.
5. **Instagram / Telegram:** интеграция, если канал подключён; пациента идентифицируем по внешнему id канала.
10. **Источники:** справочник в таблице, системные значения (WhatsApp, Instagram, Telegram, сайт, 2GIS) не удаляются.
11. **Источник пациента vs сделки** (решение разработчика): у пациента — источник первого обращения, заполняется автоматически из первой сделки и не меняется; у каждой сделки — свой.
12. **Перенос между воронками:** настраивается (по умолчанию — первая стадия целевой воронки, пользователь может выбрать).
13. **Отказ не переоткрывается:** повторное обращение → новая сделка.
14. **Теги:** и у пациента, и у сделки.
15. **Чек-лист стадии блокирует** переход на следующую стадию, пока не отмечены обязательные пункты.
16. **Непрочитанное** (решение разработчика): отметка прочтения по сделке/диалогу целиком (прочитал любой сотрудник — прочитано); персональные отметки — позже при необходимости.

## Интеграции

2. **Мессенджеры — через API Wazzup24** (WhatsApp, Instagram, Telegram). Собственный WhatsApp-сервис на QR/Baileys не делаем. Архитектура — универсальный `channel_connection` с адаптерами; Wazzup — первый адаптер (входящие через webhook → Edge Function, исходящие — через Wazzup API).

## Автоматизации

Вопросы 17–21 отложены до этапа 5–6.

## Технические

- Часовой пояс по умолчанию `Asia/Almaty`, хранится в настройках организации.
- Телефоны нормализуются к `+7XXXXXXXXXX`.
- RLS-тесты — SQL-тесты на Postgres с эмуляцией схемы `auth` Supabase (полный локальный Supabase в облачной среде разработки недоступен).

## Развитие после этапа 8 (согласовано)

- **Расписание врачей как в МИС не делаем.** Вместо него — интеграция с МИС: внешние id пациентов и сделок, визиты и оплаты из МИС двигают сделку. Коннекторы — по запросу клиник.
- Берём в работу: поля «Врач», «Сумма консультации», «Предоплата»; контроль скорости ответа с уведомлением руководителю; уведомления сотрудникам (колокольчик, браузер, Telegram); быстрые ответы в чате по «/»; повторные продажи (напоминание через N месяцев после лечения); массовая рассылка по сегменту с антибан-лимитами; телефония (Binotel, Zadarma, Mango, общий формат); журнал действий; импорт из Excel и amoCRM.
- **Мобильную версию не делаем** (решение заказчика): CRM работает в браузере на компьютере.
