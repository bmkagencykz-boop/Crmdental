# Этап 4. WhatsApp, Instagram, Telegram через Wazzup24 и «Входящие»

## Что появилось

**Подключение** (Настройки → Мессенджеры, для владельца и руководителя):
- вставляете API-ключ Wazzup24;
- CRM проверяет ключ, забирает подключённые каналы (номера WhatsApp, аккаунты Instagram и Telegram) и сама регистрирует у Wazzup24 адрес для входящих;
- ключ хранится только на сервере и в интерфейсе больше не показывается.

**Входящее сообщение само становится обращением:**
- **Пациента ищем:** в WhatsApp — по номеру в любом написании (`8 707…` и `+7 (707)…` — один и тот же пациент); в Instagram и Telegram — по id чата, поэтому смена ника не создаёт дубль.
- **Если пациента нет**, он создаётся: имя из контакта, телефон, источник по мессенджеру.
- **Сделка:** сообщение попадает в последнюю обновлённую открытую сделку пациента. Если открытой нет (например, прошлая закрыта отказом), создаётся новая сделка на первом этапе основной воронки, без ответственного (распределение — этап 5).
- **Повторы вебхука** не дублируют сообщения.
- **Ответы, отправленные прямо с телефона**, тоже попадают в CRM.

**Экран «Входящие»:** слева все диалоги клиники, свежие сверху. Есть фильтр «Непрочитанные» и поиск по имени и телефону. Справа — переписка и поле ответа. Из диалога можно открыть сделку. На иконке «Входящие» в меню — число диалогов с непрочитанными.

**Карточка сделки:** сообщения стоят в общей ленте рядом с заметками, звонками и историей. Поле ввода по умолчанию открыто на «Сообщение». Ответ уходит в тот мессенджер и тот чат, откуда пациент писал последним. Если пациент ещё не писал — в WhatsApp на его номер. У исходящих видно статус: отправлено ✓, доставлено ✓✓, прочитано (синие ✓✓), не доставлено.

**Канбан:** зелёный значок с числом непрочитанных на карточке сделки. Сообщения отмечаются прочитанными, когда сотрудник открывает сделку или диалог.

**Время первого ответа:** первое исходящее сообщение записывается в сделку (`first_response_at`) — пригодится для отчётов (этап 7).

## Как подключить клинику

1. В Wazzup24 подключить каналы (WhatsApp, Instagram, Telegram) и скопировать API-ключ (Настройки → API).
2. В CRM: Настройки → Мессенджеры → вставить ключ → «Подключить».
3. Для продакшна edge-функциям нужна переменная `WEBHOOK_BASE_URL`, если публичный адрес функций отличается от `SUPABASE_URL/functions/v1`.

## Как устроено

- **Таблицы:**
  - `messenger_integrations` — ключ и токен вебхука. Нет ни одной политики и отозваны все права: читают только edge-функции.
  - `messenger_channels`, `patient_chats`, `messages`. Миграция `20260930000000_stage4_messengers.sql`.
- **Приём:** edge-функция `wazzup_webhook` (`?token=` определяет клинику) → `public.ingest_message()` (вся логика в базе, покрыта SQL-тестами). Статусы доставки → `public.update_message_status()`.
- **Отправка:** edge-функция `messenger_send`. Сделку читает с правами сотрудника, поэтому администратор может писать только в видимые ему сделки. Чат выбирает `chooseRoute()` из `_shared/messenger.ts`.
- **Подключение:** edge-функция `messenger_connect`.
- **Права:**
  - сотрудники читают сообщения только видимых им сделок (те же правила, что и для сделок);
  - изменить могут только отметку «прочитано» (права на колонку `read_at`);
  - создать или переписать сообщение из клиента нельзя.
- **Новые сообщения** появляются без перезагрузки: списки опрашивают базу каждые 15 секунд.
- **Демо:** диалоги сгенерированы, «отправка» сохраняет сообщение без Wazzup24.

## Тесты

- SQL [`006_messages`](../../supabase/tests/006_messages.test.sql):
  - новый номер создаёт пациента и сделку;
  - повтор вебхука не дублирует сообщение;
  - поиск по телефону, выбор последней обновлённой сделки;
  - после отказа создаётся новая сделка;
  - Instagram по id чата;
  - эхо и время первого ответа;
  - статусы доставки;
  - изоляция клиник и токенов;
  - права сотрудников (подделать сообщение, прочитать ключ, вызвать функцию вебхука — нельзя);
  - видимость для администратора.
- Unit: `supabase/functions/_shared/messenger.test.ts` — формат Wazzup24, каналы, выбор чата для ответа. Плюс `timeline.test.ts`.
- e2e [`messenger.spec.ts`](../../e2e/messenger.spec.ts):
  - сообщение с нового номера → значок в меню и на канбане → диалог во «Входящих» → прочитано → лента сделки;
  - пациент, заведённый вручную, узнаётся по номеру;
  - статус подключения в настройках.

## Известные ограничения

- **Без живого ключа Wazzup24 не проверено:** реальная отправка и приём через Wazzup24. Функции построены по API v3 из [документации Wazzup24](https://wazzup24.com/help/api-en/). e2e имитирует вебхук вызовом той же функции базы.
- **Edge-функции в песочнице не запускались:** они не смогли скачать зависимости с jsr.io. Логика вынесена в базу и в модуль `_shared/messenger.ts`, которые покрыты тестами.
- **Вложения:** входящие фото и файлы показываются ссылкой. Отправка вложений из CRM — позже.
- **Групповые чаты WhatsApp, VK и Avito** игнорируются.
