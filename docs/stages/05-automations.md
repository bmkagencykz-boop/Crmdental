# Этап 5. Распределение лидов, автозадачи, чек-листы этапов

## Что появилось

**Распределение новых обращений** (Настройки → Распределение). Касается обращений «снаружи» — из мессенджеров, позже и с сайта. Сделку, которую создал сотрудник, никто не перераспределяет. Три режима:
- **Распределяет руководитель** — сделка приходит без ответственного, руководитель назначает её вручную.
- **По очереди** — каждое новое обращение получает следующий сотрудник из выбранного списка. Отключённые сотрудники пропускаются.
- **Кто первый ответил** — сделка ждёт без ответственного и достаётся тому из выбранных, кто первым ответит пациенту. Если никто не выбран, взять может любой сотрудник.

Вместе со сделкой ответственным становится и пациент (если у него ещё нет ответственного), а также все открытые задачи сделки без исполнителя.

**Автозадачи** (Настройки → Автозадачи). Правило создаёт задачу при создании сделки или при переходе на выбранный этап. У правила задаются тип задачи, текст и срок (через N минут, часов или дней). Задача назначается ответственному по сделке. Правило можно выключить, не удаляя.

Каждая клиника получает два правила по умолчанию:
- при создании сделки — «Связаться с пациентом по новому обращению» (звонок, через 15 минут);
- при переходе на «Пришёл на консультацию» — «Отправить план лечения и стоимость» (сообщение, через 1 день).

**Чек-листы этапов** (Настройки → Воронки → кнопка с галочками у этапа). Пункты, которые нужно выполнить на этапе. В карточке сделки появляется блок «Чек-лист этапа» с прогрессом. Пока не отмечены все пункты, база не пустит сделку дальше по воронке: ни перетаскиванием на канбане, ни через форму — появится ошибка «Выполните чек-лист этапа «…»». Отказ возможен всегда, вернуться на прошлый этап тоже можно.

## Как устроено

- Миграция `20261001000000_stage5_automations.sql`:
  - поля распределения в `organization_settings`;
  - таблицы `task_rules`, `stage_checklist_items`, `deal_checklist_checks`;
  - правила по умолчанию для уже существующих клиник.
- **Распределение по кругу:** `private.next_responsible()` вызывается из `handle_deal_before_write`, когда сделку создаёт не пользователь, а система (вебхук). Строка настроек блокируется на время выбора, чтобы два одновременных лида не достались одному человеку.
- **«Кто первый ответил»:** `private.handle_message_created` — первое исходящее сообщение выбранного сотрудника.
- **Автозадачи:** `private.create_rule_tasks()`, вызывается из `handle_deal_after_write`.
- **Чек-лист:** проверяется в `handle_deal_before_write`, в демо — `checkStageChecklist` в `commons/domain.ts`.
- **Права:** правила и чек-листы меняют только владелец и руководитель. Отмечать пункты может любой сотрудник, который видит сделку.

## Тесты

- SQL [`007_automations`](../../supabase/tests/007_automations.test.sql):
  - правила по умолчанию;
  - задача при создании сделки и при переходе на этап;
  - права на настройки и изоляция клиник;
  - распределение по кругу с пропуском отключённых;
  - «кто первый ответил» — только среди выбранных, задачи переходят к нему;
  - чек-лист блокирует движение вперёд, но не отказ.
- Unit: `checkStageChecklist`, `ruleTasks`, `splitDelay`.
- e2e [`automations.spec.ts`](../../e2e/automations.spec.ts):
  - новая сделка сразу получает задачу;
  - чек-лист из настроек блокирует переход, а после отметки пропускает;
  - распределение по кругу, настроенное через интерфейс, раздаёт обращения из мессенджера по очереди.

## Известные ограничения

- Распределение по кругу не учитывает рабочее время и загрузку сотрудников.
- Сотрудник не получает уведомление о назначении: новое обращение видно в его задачах («Связаться с пациентом») и на канбане.
- Автоматические сообщения пациентам по шаблонам — этап 6.
