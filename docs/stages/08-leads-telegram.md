# Этап 8. Заявки с сайта, Tilda, 2GIS и собственный Telegram-бот

## Что появилось

**Заявки с сайта** (Настройки → «Заявки с сайта», для владельца и руководителя):
- у каждой клиники свой адрес для заявок `…/functions/v1/leads_webhook?token=…`, кнопки «Копировать» и «Новый адрес» (старый адрес сразу перестаёт работать);
- готовый HTML-код формы для сайта (имя, телефон, комментарий, UTM-метки страницы) — вставляется как есть;
- инструкции для Tilda и 2GIS;
- кнопка «Отправить тестовую заявку»: отправляет заявку на адрес так же, как сайт. Тестовый пациент «Тестовая заявка» появляется на канбане.

**Заявка сама становится обращением:**
- **Поля:** `phone` (обязательно), `name`, `source`, `service`, `comment`, `utm_*`. Понимаются и названия полей Tilda (`Name`, `Phone`, `Textarea`…). Остальные поля формы (например, «Удобное время») добавляются в комментарий.
- **Формат:** JSON или обычная форма (`application/x-www-form-urlencoded`, `multipart/form-data`). Сайт может отправлять `fetch` прямо из браузера: адрес отвечает на CORS-запросы.
- **Пациент:** ищется по телефону в любом написании (`8 701…`, `+7 (701)…`). Если его нет — создаётся с именем из формы и источником заявки.
- **Сделка:** заявка попадает в последнюю обновлённую открытую сделку пациента. Если открытой нет, создаётся новая на первом этапе основной воронки, с источником и услугой из формы.
- **Распределение и задачи:** новая сделка распределяется по правилам клиники (этап 5) и получает автозадачу «Связаться с пациентом по новому обращению».
- **Заметка:** каждая заявка — заметка в сделке: «Заявка (2GIS)» или «Повторная заявка (Сайт)», затем имя, телефон, услуга, комментарий и UTM-метки. Так повторное обращение видно в ленте.
- **Источник:** код или название из справочника (`website`, `2gis`, «Сайт», «2GIS», любой свой источник), без учёта регистра. Если не указан — «Сайт». Если не найден — «Сайт», а исходное значение пишется в заметку.
- **Услуга:** название из справочника услуг, без учёта регистра. Если не найдена — поле услуги остаётся пустым, а текст пишется в заметку.
- **Дубли:** одна и та же форма с того же телефона за 5 минут сохраняется один раз. Одновременные отправки одного телефона обрабатываются по очереди.

**Собственный Telegram-бот** (Настройки → Мессенджеры → Telegram-бот):
- клиника вставляет токен бота из @BotFather → «Подключить бота». CRM проверяет токен (`getMe`), хранит его только на сервере и регистрирует адрес для входящих (`setWebhook`) с секретом: каждое обновление Telegram подписывает заголовком `X-Telegram-Bot-Api-Secret-Token`, чужие запросы отклоняются;
- в настройках видно «Бот подключён: @имя_бота», бота можно отключить или заменить другим;
- **Пациент** определяется по id чата Telegram, смена ника не создаёт дубль. Новый пациент получает имя из профиля, ник и источник Telegram;
- **«Поделиться номером»:** телефон сохраняется у пациента. Если этот номер уже есть у другого пациента, а пациент из бота «пустой» (только этот чат, без телефона, заметок пациента и звонков), он объединяется с известным: его сделки, сообщения и чат переходят к известному пациенту. Иначе телефон просто сохраняется. Новый чат, который первым же сообщением делится известным номером, сразу привязывается к этому пациенту;
- **Фото, файлы, голосовые** показываются подписью «[Фото]», «[Файл plan.pdf]» и т. п. Файлы не скачиваются: ссылка на файл Telegram раскрыла бы токен бота;
- **Ответ** из карточки сделки или «Входящих» уходит в чат, откуда пациент писал последним. Если это бот — через Bot API `sendMessage`. Статус: «отправлено» или «не доставлено» с текстом ошибки (например, пациент заблокировал бота);
- **Wazzup24 и бот работают вместе:** Telegram через Wazzup24 и собственный бот — разные каналы. Один и тот же человек в них — два разных чата.

## Как подключить клинику

**Форма на своём сайте:**
1. Настройки → «Заявки с сайта» → «Копировать код» в блоке «Форма для сайта».
2. Вставить код на страницу сайта. Оформление — стилями сайта.
3. Нажать «Отправить тестовую заявку» или отправить форму с сайта: на канбане появится сделка.
4. Своя форма тоже подойдёт: `POST` на адрес для заявок с полями `name`, `phone`, `comment`…

**Tilda:**
1. Настройки сайта → Формы → Webhook: вставить адрес для заявок.
2. В блоке формы: Контент → Сервисы приёма данных → отметить Webhook.
3. Поля `Name`, `Phone`, `Comment` Tilda называет так по умолчанию. Тестовый запрос Tilda (`test=test`) принимается без создания сделки.

**2GIS:**
1. В кабинете 2GIS для бизнеса указать в карточке клиники ссылку на сайт с `?utm_source=2gis`: заявки с этой страницы придут с меткой.
2. Формам и сервисам записи, которые умеют вызывать webhook, дать адрес для заявок и поле `source=2gis`: заявка придёт с источником 2GIS.
3. Звонки из 2GIS записываются вручную с источником 2GIS.

**Telegram-бот:**
1. В Telegram открыть @BotFather → `/newbot`, задать имя и ник бота, скопировать токен.
2. В CRM: Настройки → Мессенджеры → Telegram-бот → вставить токен → «Подключить бота».
3. Разместить ссылку `t.me/ник_бота` на сайте, в Instagram, в 2GIS.
4. Для продакшна edge-функциям нужна переменная `WEBHOOK_BASE_URL`, если публичный адрес функций отличается от `SUPABASE_URL/functions/v1`. Интерфейс берёт адрес для заявок из `VITE_WEBHOOK_BASE_URL`, иначе из `VITE_SUPABASE_URL/functions/v1`.

## Как устроено

- **Миграция** `20261004000000_stage8_leads_telegram.sql`, схема — `supabase/schemas/10_leads.sql`.
- **Таблицы:**
  - `lead_integrations` — токен адреса для заявок. Нет ни одной политики, права отозваны: читают только edge-функции. Владелец и руководитель получают адрес через `public.lead_webhook_token()` (создаёт токен при первом обращении) и меняют через `public.regenerate_lead_webhook_token()`; обе функции проверяют роль;
  - `lead_submissions` — журнал заявок: телефон, хэш формы (для дублей), содержимое, пациент и сделка. Читают владелец и руководитель своей клиники;
  - `telegram_bots` — токен бота, его id и ник, токен адреса и секрет заголовка. Только для edge-функций, статус — через `public.telegram_bot_status()`.
- **Новый транспорт** `telegram_bot` в `messenger_channels`, `patient_chats`, `messages` (канал бота — `tgbot:<id бота>`, источник — системный «Telegram»).
- **Заявки:** edge-функция `leads_webhook` (`verify_jwt = false`) разбирает тело (`_shared/leads.ts`) → `public.ingest_lead(token, lead)` (вся логика в базе, только service_role). Коды ответа: 200 — принято, 400 — нет телефона, 401 — неизвестный токен.
- **Бот:**
  - `telegram_connect` — подключение и отключение (владелец и руководитель);
  - `telegram_webhook` (`verify_jwt = false`) — `_shared/telegram.ts` превращает Update в формат `ingest_message` → `public.ingest_telegram_message(token, secret, message)`: проверяет секрет, обрабатывает «Поделиться номером» (`private.link_telegram_phone`) и вызывает `public.ingest_message`;
  - `public.ingest_message` расширен минимально: транспорт `telegram_bot` определяет клинику по токену бота, а не Wazzup24;
  - `messenger_send` — выбирает чат через `chooseRoute()`, учитывая только подключённые каналы (`usableChannels`), и отправляет через Wazzup24 или Bot API.
- **Демо:** адрес `https://demo.dentalcrm.kz/functions/v1/leads_webhook?token=demo-token`. Тестовая заявка создаёт пациента, сделку и заметку в демо-данных. Бот показан подключённым (`@zhemchug_dental_bot`), часть диалогов идёт через него.

## Известные ограничения

- **Без живых запросов не проверено:** реальные вызовы Telegram Bot API (`getMe`, `setWebhook`, `sendMessage`) и запросы Tilda. Функции построены по [документации Bot API](https://core.telegram.org/bots/api). e2e имитирует заявку вызовом той же функции базы, что и вебхук.
- **Edge-функции в песочнице не запускались:** они не смогли скачать зависимости с jsr.io. Логика вынесена в базу и в модули `_shared/leads.ts`, `_shared/telegram.ts`, которые покрыты тестами. e2e в песочнице не запускались.
- **Адрес для заявок публичный** (он есть в коде сайта): от спама защищает только отсечение дублей. Если адрес начали использовать чужие — «Новый адрес».
- **У 2GIS нет своего вебхука заявок:** заявки из 2GIS приходят через сайт с меткой или через сервисы, которые умеют вызывать webhook.
- **Telegram-бот:** файлы не скачиваются и не отправляются, только текст. Групповые чаты игнорируются. Один бот на клинику.
