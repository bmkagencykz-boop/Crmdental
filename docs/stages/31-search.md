# Этап 31. Глобальный поиск и удобство работы

## Что появилось

**Поиск в верхней строке** — как верхний поиск amoCRM и поле «Поиск пациента» в МИС. Поле «Поиск пациента, телефона, сделки…» видно на любой странице. Встать в него можно мышью, клавишей «/» или Ctrl+K (⌘K на Mac). Результаты появляются сразу под полем, по группам:
- **Пациенты** — ФИО, телефон (совпавший номер выделен), дата рождения, номер карточки (№ пациента в CRM и номер в МИС, если пациент пришёл из МИС);
- **Сделки** — название и № сделки, пациент, этап с цветом, ответственный, сумма;
- **Задачи** — тип, текст, пациент, срок (выполненные — зачёркнуты);
- **Сообщения** — фрагмент переписки вокруг найденных слов, от кого (пациент или клиника), пациент, время.

Стрелки ↑ ↓ выбирают строку, Enter открывает её (без выбора — первую, самую точную), Esc очищает поле, второй Esc закрывает список. «Показать все» открывает страницу поиска: до 50 результатов каждого вида.

Пока поле пустое, в списке — **«Недавние»**: последние 8 пациентов и сделок, которые сотрудник открывал (у каждого сотрудника свои, хранятся в браузере).

**Как ищется:**
- **Телефон** — в любом написании: «+7 701 555 12 34», «87015551234», «7015551234», «555 12 34», «(701) 555-12». Можно набрать только часть цифр. Точное совпадение номера — всегда первым.
- **ФИО** — без учёта регистра, по началу слов и в любом порядке: «ив ан» найдёт «Иванова Анна». «Е» и «ё» не различаются («Семенов» = «Семёнов»). Латиница работает так же («aig» → «Aigerim»).
- **Смешанный запрос** — «Иванова 701»: фамилия и цифры телефона вместе.
- **Номера** — «#123» или «№123» (а также короткое число до 6 цифр): карточка пациента и сделка с этим номером. Номер пациента в МИС ищется как есть («MIS-7788»).
- **Сделки** — по названию, пациенту и его телефону; **задачи** — по тексту и пациенту сделки; **сообщения** — по фразе из текста.

**Права.** Поиск показывает только то, что сотрудник и так может открыть: если администратор видит только свои сделки (Настройки → Доступ), чужие сделки, их задачи и переписка в поиске не появятся — даже по номеру. Пациенты общие для клиники, как и раньше. Данные другой клиники не находятся никогда.

**Быстрое создание.** Если по полному номеру телефона никто не найден, в списке есть строка «+ Новый пациент с номером +7 701 555 12 34» — откроется карточка нового пациента с уже заполненным номером.

**Горячие клавиши** (список — по «?» или кнопке «?» в верхней строке). Работают и в русской раскладке; в полях ввода работает только Ctrl+K.

| Клавиши | Действие |
|---|---|
| / или Ctrl+K | Поиск |
| ? | Список горячих клавиш |
| N | Новая сделка |
| Shift+N | Новый пациент |
| g, затем h | Рабочий стол |
| g, затем d | Сделки |
| g, затем i | Входящие |
| g, затем t | Задачи |
| g, затем s | Расписание |
| g, затем p | Пациенты |
| g, затем r | Отчёты |

**Удобство интерфейса:**
- **Компактная шапка.** Название раздела («Сделки», «Пациенты»…) переехало из огромного заголовка над страницей в верхнюю строку рядом с логотипом, а сама строка стала ниже. На каждой странице освободилось около 110 пикселей по высоте — канбан, списки и карточки начинаются сразу под шапкой. В карточке пациента больше нет двух заголовков подряд («Пациенты» и ФИО).
- **Телефоны читаются.** В списке пациентов, в карточке пациента (включая WhatsApp) и в списке сделок номера показываются как «+7 701 555 12 34», а не «+77015551234». Ссылка для звонка — прежняя.

## Как устроено

- Миграция `20261031000000_search.sql` (схема `supabase/schemas/31_search.sql`):
  - расширение `pg_trgm` (в схеме `extensions`, как принято в Supabase);
  - неизменяемые функции нормализации: `private.search_norm` (нижний регистр для кириллицы, казахских букв и латиницы независимо от локали базы, ё → е), `private.patient_search_name` (« фамилия имя отчество» с ведущим пробелом, чтобы искать по началу слова), `private.phones_search_digits` (цифры всех номеров);
  - GIN-индексы `gin_trgm_ops` по ФИО и цифрам телефонов пациентов, по названию сделок, тексту задач и тексту сообщений — шаблоны `'%…%'` идут по индексу;
  - `public.global_search(q, max_per_kind)` — `security invoker`, поэтому что найдётся, решает RLS (видимость сделок, изоляция клиник). Возвращает JSON `{patients, deals, tasks, messages}`, не больше `max_per_kind` (1–50) каждого вида. Порядок пациентов: точный телефон → номер карточки → точное ФИО → ФИО с начала → остальные совпадения имени → часть телефона, затем последняя активность. Сделки: № сделки → точный телефон → по началу имени/названия → прочее, открытые выше закрытых.
- Разбор запроса совпадает с поиском в списках (`phoneQueryDigits`): запрос из цифр, пробелов, «+», скобок и дефисов — телефон, ведущие 8/7 перед 7XX отбрасываются.
- Двойник для демо: `src/components/atomic-crm/search/globalSearch.ts` — те же правила разбора, сравнения и порядка на TypeScript; `providers/fakerest/search.ts` применяет его с правилом видимости сделок.
- Интерфейс: `search/GlobalSearch.tsx` (поле и выпадающий список, «Недавние» — ra store с ключом `search.recent.<id сотрудника>`, запоминаются все открытые карточки пациентов и сделок), `search/SearchResults.tsx` (строки результатов с подсветкой), `search/SearchPage.tsx` (`/search?q=`), `search/shortcuts.ts` + `search/Shortcuts.tsx` (горячие клавиши по `KeyboardEvent.code`, поэтому не зависят от раскладки; в диалогах и полях ввода не срабатывают).
- Номер для «+ Новый пациент» передаётся в `/patients/create?phone=…`.
- Форматирование номеров: `misc/formatPhone.ts`.

## Тесты

- SQL [`031_search`](../../supabase/tests/031_search.test.sql):
  - телефон в разных написаниях и частями, точный номер — первым и без соседних номеров;
  - ФИО: регистр, начало слов, порядок слов, ё/е, латиница, смешанный запрос, символы `%` и `_` как обычный текст, слишком короткий запрос;
  - номер карточки (#, №), номер в МИС;
  - сделки (название, пациент, телефон, номер, этап, ответственный, сумма), задачи, сообщения с фрагментом;
  - ограничение `max_per_kind`;
  - изоляция клиник (тот же пациент с тем же номером в другой клинике);
  - видимость «только свои сделки»: чужая сделка, её задачи и сообщения не находятся (даже по номеру), пациенты находятся; ответственный находит свою сделку;
  - анонимный пользователь не может искать.
- Unit: `search/globalSearch.test.ts` (те же случаи, что в SQL-тесте, демо-поиск с видимостью, подсветка, быстрое создание), `search/shortcuts.test.ts` (клавиши, последовательности «g x», русская раскладка, поля ввода, «Недавние»).
- e2e [`globalSearch.spec.ts`](../../e2e/globalSearch.spec.ts): поиск по телефону в другом написании и переход в карточку клавиатурой, сделка по названию, «Показать все», «+ Новый пациент с номером…», горячие клавиши, «Недавние», менеджер не находит чужую сделку.

## Известные ограничения

- Нет транслитерации: «Ivanova» не найдёт «Иванова».
- Нет поиска с опечатками (нечёткого совпадения), хотя `pg_trgm` это позволяет — можно добавить позже.
- Сообщения ищутся только по тексту; телефон в тексте сообщения не ищется.
- «Недавние» хранятся в браузере: на другом компьютере список свой.
- Поиск по заметкам, звонкам и файлам не делался.
