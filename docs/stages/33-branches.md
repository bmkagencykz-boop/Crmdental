# Этап 33. Филиалы: сеть клиник с несколькими адресами

## Что появилось

**Справочник «Филиалы»** (Настройки → Клиника и доступ → «Филиалы», владелец и руководитель): название, адрес, телефон, порядок, «Активен». Филиал со сделками удалить нельзя — его выключают (выключенный скрыт из выбора, старые сделки его сохраняют). В том же разделе:

- **Сотрудники** — таблица «сотрудник × филиал»: сотрудник работает в одном или нескольких филиалах;
- **Врачи и кресла** — филиал каждого врача и кресла или «Все филиалы» (работает везде);
- **Куда приходят заявки** — филиал каждого канала мессенджеров; подсказки для форм сайта (поле `branch`) и телефонии (номер филиала);
- **Привязать к филиалу** — сделки и визиты без филиала одним нажатием переходят в выбранный филиал (когда клиника открывает второй адрес).

**Клиника с одним адресом выглядит как раньше.** Интерфейс филиалов появляется со второго активного филиала:

- **переключатель в верхней строке** «Все филиалы / Филиал …» (запоминается для каждого сотрудника): канбан и список сделок, задачи (список и календарь), расписание и отчёты показывают выбранный филиал;
- **расписание** филиала — только его врачи и кресла и общие («Все филиалы»); визиты — этого филиала и без филиала. Вид расписания не менялся, цвета врачей прежние;
- **отчёты** — фильтр «Филиал» рядом с остальными (по умолчанию — филиал из верхней строки); отчёт «Скорость» по филиалу показывает его сотрудников и тех, у кого есть работа в этом филиале;
- **сделка** — поле «Филиал» на странице сделки и в форме (новая сделка — в филиале из верхней строки), название филиала на карточке канбана;
- **права доступа** — у сделок и задач новая область **«Мой филиал»** между «Все» и «Только свои».

**Пациенты общие для сети** — одна карточка на все филиалы.

**Что принадлежит филиалу:** сотрудники, врачи, кресла, сделки (куда идёт пациент), визиты (по креслу, иначе по врачу, иначе по сделке), задачи (филиал их сделки), каналы мессенджеров.

**Новые заявки попадают в свой филиал:**

- сообщение из канала, привязанного к филиалу, открывает сделку в этом филиале;
- заявка с сайта с полем `branch` (название филиала без учёта регистра или его номер) — в этот филиал, в заметке заявки строка «Филиал: …»;
- звонок: если АТС передаёт номер клиники, на который позвонили (`line`; Zadarma `called_did`, Mango `line_number`, Binotel `pbxNumberData.number`, общий формат `line`/`did`), — в филиал с этим телефоном; иначе — в филиал ответившего сотрудника, если он работает в одном филиале;
- сделка, созданная без филиала, получает филиал врача, иначе — филиал ответственного (или создающего её сотрудника), если он работает в одном филиале.

**Распределение заявок филиала** («По очереди», «Кто первый ответил» и уведомления о неназначенной заявке) идёт только среди выбранных сотрудников этого филиала. Если никто из выбранных там не работает — среди всех выбранных, чтобы заявка не потерялась. Заявки без филиала распределяются как раньше.

### Почему филиал может быть пустым, а не «филиал по умолчанию»

Выбран вариант **«пусто = общий для сети»**, без создания филиала по умолчанию:

- у существующих клиник ничего не меняется и ничего не переносится; клиника без филиалов (или с одним) работает ровно как раньше;
- все, кто создаёт сделки — формы, мессенджеры, телефония, импорт, API, салесбот, МИС, — продолжают работать, не зная о филиалах;
- пустой филиал естественен для врача или кресла, которые работают везде, и для заявки из канала, не привязанного к филиалу;
- когда клиника открывает второй адрес, владелец одной кнопкой «Привязать к филиалу» переносит старые сделки и визиты в первый филиал.

## Как устроено

- Схема `supabase/schemas/33_branches.sql`, миграция `20261102000000_branches.sql`:
  - таблицы `branches` (справочник) и `sales_branches` (сотрудник ↔ филиал); столбец `branch_id` у `deals`, `doctors`, `chairs`, `visits`, `tasks`, `messenger_channels` (составные внешние ключи — только филиал своей клиники). Филиал со сделками, визитами или задачами не удаляется; у врачей, кресел и каналов при удалении филиала — «Все филиалы»;
  - триггер `deal_assign_branch` (раньше распределения по алфавиту) — филиал новой сделки по врачу или ответственному; `task_branch` и `deal_branch_changed` — `tasks.branch_id` всегда равен филиалу сделки (по нему фильтруются списки задач); `visit_branch` — филиал визита;
  - `private.branch_pool` — кому достаётся заявка филиала; `private.next_responsible(org_id, branch)` (очередь), `handle_message_created` («кто первый ответил»), `private.deal_audience` (уведомления) его используют;
  - `private.find_branch` — филиал по названию или номеру (поле `branch` формы сайта);
  - `public.assign_branch_to_unassigned(branch)` — «Привязать к филиалу» (владелец и руководитель, системная запись без автоматизаций и уведомлений);
  - `deals_summary` — в конце `branch_id`, `branch_name`;
  - журнал действий: изменения филиалов (сущность «Филиал»).
- **Права.** В `private.access_scopes` новая область `branch` у сделок и задач (для пациентов её нет — они общие). `private.current_branch_ids()` (в `01_tables.sql`, рядом с `private.access_scope`) — филиалы текущего сотрудника. «Мой филиал» = свои строки + строки филиалов сотрудника + строки без филиала. Политики просмотра, правки и удаления сделок и задач перенесены из `05_policies.sql` в `33_branches.sql` (они читают `branch_id`, который добавлен здесь); `private.deal_visible` проверяет то же. Всё, что проверяет видимость сделки (заметки, оплаты, переписка, визиты, планы лечения, салесбот, расписание, неразобранное), следует за «Мой филиал» автоматически. `my_access_rights()` возвращает ещё `branch_ids`.
- **Отчёты.** У `report_conversion`, `report_speed`, `report_lost_reasons`, `report_money`, `report_plan_services` и `private.report_deal_progress` — последний необязательный параметр `filter_branch_id` (старые сигнатуры удалены в миграции).
- **Входящие:** `ingest_message` берёт филиал канала, `ingest_lead` — поле `branch`, `ingest_call` — поле `line` (номер клиники; edge-функция `telephony_webhook` передаёт его, `_shared/telephony.ts`), иначе филиал сотрудника по добавочному.
- **Интерфейс** (`branches/`): `branches.ts` — правила на TypeScript (когда показывать, текущий филиал, фильтр, врачи и кресла филиала, филиал новой сделки и визита, пул распределения, «Мой филиал»); `useBranches.ts` — справочник и текущий филиал (ключ `branches.current.<сотрудник>`); `BranchSwitcher.tsx` — переключатель в верхней строке; `BranchesSettings.tsx` — раздел настроек. Фильтр филиала — постоянный фильтр `branch_id` списков сделок (канбан и список) и задач; расписание фильтрует колонки и визиты в браузере. Область «Мой филиал» в таблице прав появляется со второго филиала; экспорт при «Мой филиал» выгружает строки филиалов сотрудника.
- **Демо** (`providers/fakerest/branches.ts`, `dataGenerator/branches.ts`): «Клиника на Достык» и «Филиал на Абая» — на Абая ортодонт и детский стоматолог, детское кресло, четверть сделок, Instagram-канал и сотрудник `abaya@demo.kz` с правом «Мой филиал». Те же правила, что в базе: филиал новой сделки, задачи за сделкой, визит по креслу, «кто первый ответил» в филиале, фильтр отчётов, «Привязать к филиалу», запись справочника только владельцем и руководителем.

  - справочник: владелец и руководитель правят, администратор только читает и не выбирает себе филиал; журнал;
  - филиал новой сделки (заданный, по врачу, по ответственному, по создающему; нет угадывания для сотрудника двух филиалов), врач меняет филиал сделки без филиала, снятый вручную филиал не возвращается;
  - задачи следуют за сделкой; визит — по креслу, врачу, сделке, при переносе к врачу другого филиала;
  - «Мой филиал»: сделки своих филиалов и без филиала, свои сделки другого филиала, правка чужого филиала запрещена, задачи, визиты, `private.deal_visible`, сотрудник двух филиалов; для пациентов области нет;
  - заявки: канал филиала (привязывает только владелец/руководитель, другие столбцы канала не пишутся), «по очереди» внутри филиала, филиал без выбранных сотрудников, заявка без филиала, «кто первый ответил», уведомления; форма сайта по названию и номеру, неизвестный филиал; звонок по номеру филиала и по сотруднику;
  - отчёты с фильтром филиала (все пять), «Скорость» по сотрудникам филиала;
  - «Привязать к филиалу», удаление филиала со сделками запрещено, врачи удалённого филиала становятся общими;

## Известные ограничения

- Часовой пояс у филиала не задаётся: вся сеть работает в часовом поясе клиники.
- Фильтр филиала строгий: при выбранном филиале сделки и задачи без филиала видны только в «Все филиалы». Колонка «Неразобранное» и раздел «Входящие» показывают заявки всех филиалов, чтобы ни одна не потерялась.
- Врач работает в одном филиале или во всех («Все филиалы»); расписание врача по филиалам (дни в разных адресах) не сделано.
- Telegram-бот клиники один, его заявки без филиала. Маркетинговый отчёт, повторные продажи, план продаж и рабочий стол филиал не учитывают (расходы на рекламу не делятся по филиалам).
- Публичный API и вебхуки не передают филиал сделки; импорт не читает столбец филиала (сделка получит филиал врача или ответственного).
- Перенос сделки в другой филиал не пишется в ленту сделки и журнал действий.
- Изменения филиалов сотрудника интерфейс узнаёт в течение 30 секунд (как права), база применяет их сразу.
